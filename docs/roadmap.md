# HashCalculator 开发路线图

**项目**：`e:\Project\HashCalculator`（Rust + egui）
**状态**：0.4.1 已发布；0.4.2（大文件并行优化）已完成并验证，待发 PR
**定位**：轻量、跨平台、单文件哈希计算工具（GUI 优先）
**本文用途**：给出「先做什么、后做什么、明确不做什么」的判断，作为后续排期与 PR 拆分的依据

> 已完成的大文件性能优化（约 1.6x）见 [perf-plan.md](perf-plan.md)。

## 项目定位与边界

- **是**：一个轻量、跨平台、单文件的哈希计算器，解决「算一个文件的 MD5/SHA-256 并核对」这一件事。
- **不是**：哈希工具套件、批量流水线工具、CLI-first 工具。
- **取舍准则**：任何显著增加体积、依赖或交互复杂度的功能，须先证明其收益大于定位稀释的成本。

## 现状盘点

### 已具备能力

| 能力 | 说明 |
| ---- | ---- |
| 算法 | MD5 + SHA-256（RustCrypto），后台线程计算 |
| 读取 | `memmap2` 内存映射，大文件不整体载入 |
| 交互 | 文件选择、进度条、取消、复制到剪贴板、哈希验证（✓/✗）、大写开关、状态栏 |
| 体验 | 跨平台路径、自动注册系统 CJK 字体（避免中文方框） |

### 已完成优化

MD5 与 SHA-256 **双线程并行**（零拷贝共享 mmap），大文件约 **1.6x**，哈希与 `certutil` 逐位一致。详见 [perf-plan.md](perf-plan.md)。

### 已知缺口（已核实）

| # | 缺口 | 影响 |
| - | ---- | ---- |
| 1 | 零自动化测试（无 `tests/`、无单元测试） | 正确性此前全靠手工 `certutil`，不可持续 |
| 2 | 无 CI（无 `.github/workflows`） | 每次改动无自动验证；发版靠手工 |
| 3 | 空文件返回错误而非计算标准空哈希 | 用户可感知的正确性缺陷 |
| 4 | 仅 MD5/SHA-256 | 算法单一 |
| 5 | 无拖拽、无多文件/批量、无历史记录 | 交互效率有提升空间 |
| 6 | 无 CLI 产品形态（仅开发用 `--bench`） | 无法脚本化调用 |
| 7 | 设置不持久化（`upper_case` 每次回落默认） | 体验细节缺失 |
| 8 | 计算期间文件被修改/截断时 mmap 有崩溃（SIGBUS）风险 | 健壮性隐患 |
| 9 | 无主题切换、无 i18n（界面文案中英混排） | 观感与国际用户受限 |
| 10 | 跨平台仅 Windows 实测 | Linux/macOS 未验证 |

## 主题一：正确性与回归保障【最高优先】

> 判断依据：上一轮把计算路径从顺序改为并发，这是最易引入难复现缺陷的改动；而项目没有任何自动化测试。**先把地基建起来，再谈功能。**

### P2 · 自动化测试

| 项 | 内容 |
| -- | ---- |
| 目标 | 让哈希正确性可被自动回归，覆盖并发计算路径 |
| 价值 | 高——锁住已完成的 1.6x 成果，为后续所有改动提供安全网 |
| 成本 | M |
| 风险 | 低 |
| 依赖 | 无（P3 依赖本项） |
| 验收 | ① 含**已知向量**测试（含空输入、单字节、标准短语）；② 含**边界尺寸**（1B / 恰好一块 / 一块+1B / 非对齐）；③ 测试对 `worker` 的真实计算路径生效（非镜像实现）；④ `cargo test` 全绿 |

### P1 · 空文件按标准计算

| 项 | 内容 |
| -- | ---- |
| 目标 | 空文件输出标准空输入哈希，而非报错「文件为空」 |
| 价值 | 中高——真实正确性缺陷 |
| 成本 | S |
| 风险 | 低（须确认 UI 上如何呈现 0 字节进度） |
| 验收 | 0 字节文件输出 MD5 `d41d8cd98f00b204e9800998ecf8427e`、SHA-256 `e3b0c442…2b855`，且与 `certutil` 一致 |

## 不做清单

| 项 | 理由 |
| -- | ---- |
| 继续榨取单流 MD5（SIMD / 多缓冲 / 跨块并行） | 单文件是 Merkle–Damgård 链，块间强依赖，**物理上不可按块并行**；MD5 在 x86 无硬件后端。已在 [perf-plan.md](perf-plan.md) 论证并排除 |
| 用非 RustCrypto 的自研哈希实现提速 | 无必要，且引入正确性风险；相对成熟实现收益不成比例 |
| 引入重型 GUI/Web 框架重构界面 | 与「轻量单文件工具」定位不符，成本远大于收益 |
| 为「功能齐全」而堆砌算法与批量模式 | 稀释产品定位；应以真实场景（校验下载文件）为准，而非数量 |
